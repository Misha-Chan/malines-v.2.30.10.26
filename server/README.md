# Malines Server (1.1.0.13 beta)

سيرفر اللعبة: يحفظ حالة العالم، يطبّق دورة الزمن (30 دقيقة واقعية = 3.75 يوم لعبة)، ويولّد `SAR.json` موقّعاً بمفتاح Ed25519.

## التشغيل

```bash
cd server
npm install
npm run tick      # ينشئ قاعدة البيانات + أول لقطة موقّعة
npm start         # يشغّل السيرفر على http://127.0.0.1:4000
```

أوامر مساعدة:

```bash
npm run typecheck
npm run verify -- .data/snapshots/SAR-*.json   # التحقق من التوقيع
```

## الإعدادات (متغيرات البيئة)

| المتغير | الافتراضي | الوصف |

| `PORT` | `4000` | منفذ السيرفر |

المفاتيح تُولَّد تلقائياً في `.data/keys/` (غير مرفوعة إلى Git).

## لوحة الإدارة

افتح `http://127.0.0.1:4000/console` وأدخل رمز الإدارة (افتراضياً `dev-admin`).
تتيح اللوحة:

- عرض قرارات `nDSV` والقرارات الحيّة في طابور واحد مرتّب بزمن اللعبة.
- الموافقة أو الرفض.
- تنفيذ دورة زمنية يدوياً وتوليد لقطة فورية.
- متابعة البث اللحظي ومعلومات اللقطة الموقّعة.

## البث اللحظي

`/ws` يبثّ الأحداث التالية لكل المتصلين:

| النوع | متى |
|---|---|
| `hello` | عند الاتصال (يحمل زمن اللعبة وعدد المتصلين) |
| `decision` | عند وصول قرار حيّ |
| `ndsv` | عند استيراد لقطة غير متصلة |
| `review` | عند موافقة/رفض قرار |
| `tick` | عند تنفيذ دورة زمنية |
| `snapshot` | عند توليد لقطة |

التطبيق يتصل تلقائياً ويعيد تحميل `SAR.json` عند أي حدث.

## توقيع nDSV

كل حقل في `nDSV` عدا غلاف التوقيع (`signature`، `publicKey`، `keyId`، `algorithm`)
يُسلسَل بـ `canonicalJson` (مفاتيح مرتّبة) ثم يُوقَّع بـ **ECDSA P-256 / SHA-256**.
التطبيق يولّد مفتاحه مرة واحدة ويحتفظ به، ويرسل المفتاح العام (SPKI DER، base64) مع كل لقطة.

- توقيع صحيح: يُستورد القرار ويُعاد `verified: true`.
- توقيع خاطئ أو معدَّل: `400 invalid_signature`.
- مفتاح مختلف لنفس اللاعب: `409 key_mismatch` (سياسة أول مفتاح موثوق).
- بلا توقيع: يُستورد مع `verified: false` (التوافق مع النسخ الأقدم؛ الحكم البشري يبقى الفاصل).

## أثر القرارات

عند الموافقة على قرار تُطبَّق آثاره المعروفة آلياً، ويُسجَّل حدث `decision_applied`.
إعادة مراجعة القرار نفسه لا تعيد تطبيق الأثر (العملية idempotent).

| النوع | الإجراء | الأثر |
|---|---|---|
| `military` | أي إجراء يحمل `payload.provinceId` و`payload.level` (1–5) | `garrison += level × 500` (تُرفض المقاطعات البحرية) |
| `economic` | `build_rail` مع `payload.from` و`payload.to` | `infrastructure.rail += 1` للمقاطعتين |
| `internal` | أي إجراء يحمل `payload.stability` | تعديل الاستقرار ضمن 0–100 |
| `diplomatic` | أي إجراء | يُسجَّل فقط ويُترك للحكم البشري |

الأثر المجهول لا يُرفض: يُسجَّل الحدث ليراجعه الحكم البشري.

## البنية

```
src/
  config.ts      الإعدادات والثوابت
  db.ts          SQLite (node:sqlite) + المخطط
  schema.sql     جداول العالم
  seed.ts        عالم 1900 التجريبي (10 دول، 10 مقاطعات)
  time.ts        تحويل الزمن الواقعي إلى زمن اللعبة (1:180)
  canonical.ts   تسلسل JSON ثابت للتوقيع
  signature.ts   Ed25519
  snapshot.ts    بناء SAR.json وتوقيعه وتخزينه
  tick.ts        دورة التحديث
  effects.ts     أثر القرارات المعتمدة
  ndsv.ts        التحقق من توقيع nDSV وسياسة أول مفتاح
  live.ts        إدارة اتصالات WebSocket والبث
  server.ts      Fastify API
  verify-cli.ts  أداة التحقق من التوقيع
```

## القيود الحالية (بيتا)

- SQLite بدل PostgreSQL (للنشر لاحقاً).
- لا توجد مصادقة لاعبين بعد (معرّف اللاعب يُرسل مباشرة).
- لوحة الإدارة تستخدم رمزاً واحداً (بدون حسابات متعددة).
- الخريطة التجريبية 10 مقاطعات فقط؛ الخريطة الكاملة تأتي من ملفات البيانات.
